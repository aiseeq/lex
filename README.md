# lex

Compiler for an instruction codex: every instruction file agents read is built from shared fragments by an ordered manifest.

For the command summary and agent editing guide, run `lex guide`.

- `lex import --codex DIR FILE` — split an existing file into fragments and a manifest, deterministically.
- `lex import --codex DIR --refresh FILE` — refresh fragments after the source changes.
- `lex build --codex DIR [--check] [--force] [FILE]` — build all manifests or only the output FILE; a full build skips outputs with manual edits and reports them, and with FILE `--check` checks only that output and remains read-only; `--force` requires FILE and permits overwriting that output's manual edits during a build, printing a warning with the file time and Git states when it replaces an edit outside the fragments. After changes inside the codex, `build` and `absorb` print changed paths and, for a codex inside `~/.claude` when `~/.claude-config.git` exists, a `git add` command for that repository.
- `lex absorb --codex DIR [--shared] [--force] FILE` — absorb a line edit into one fragment; if fragments changed since the last build, use `--force` to keep the file and discard those fragment edits; it prints a warning with the file time and Git states when it moves an edit outside the fragments; cross-fragment edits, and edits whose absorbed fragments would not rebuild the same file, are refused and the file is saved under `DIR/drafts`.
- `lex quotes-to-basis --codex DIR --report FILE [--apply] [--outputs-under PATH [--tree TREE]]` — move standalone `(пользователь DD.MM: «…»)` parentheses (or date-only parentheses) from fragment bodies into the one-line `основание` field. Without `--apply`, write a JSON dry-run report with moved fragment count, output byte counts, and untouched parentheses. `--apply` updates fragments, `fragment_sha256`, manifests, and selected built outputs. `--tree` maps selected outputs into a copied tree.
- `lex check --codex DIR [--staged] [--outputs-under PATH] [--tree TREE]` — check fragment references and built outputs; `--outputs-under` limits checks to outputs under a path and `--tree` is the root corresponding to `--outputs-under` and checks the same relative paths beneath it (for example, `--outputs-under MAIN/.claude --tree WT` checks `WT/rules/...`; requires `--outputs-under` and cannot combine with `--staged`); `--staged` checks Git index contents and rejects index/disk drift; in a Git worktree, an `out:` under the main checkout maps to the same file in the current tree.
- `lex check --refs-only --codex DIR` checks text references without comparing built output to fragments. Missing decision entries are errors; section, file and numbering findings are warnings, and so are skill files that no other file of the skill mentions (kind 5). Files listed in `text_refs.external` are checked as sources and produce warnings only. The decision journal defaults to `decisions.md` beside the codex. Set `"text_refs": {"decisions": "PATH"}` in `tools.json`, or use `--decisions PATH` to override it; a relative path is relative to the codex. In staged mode newly broken references from unchanged files are checked against the index and compared with HEAD.
- `tools.json` may also define `text_refs.exceptions`, for example `{"text_refs":{"exceptions":[{"path":"skills/example/SKILL.md","kind":2,"contains":"раздел «Пример»","reason":"Раздел вынесен в соседний файл."}]}}`. Each entry has a `path` relative to the output tree (the parent directory of the codex), a finding `kind` (1–5), a `contains` substring unique in that file, and a non-empty `reason`. It suppresses only findings of that kind in that file whose source line contains the substring. An entry that matches no finding, or whose substring is not unique, produces a warning identifying its key. `text_refs.external` may list absolute paths or paths starting with `~/` to files outside the built corpus. The training fixture is `internal/lex/testdata/text-refs-codex/tools.json`.
- `lex status --codex DIR` — list files changed since the last build and the command to update each one.
- `lex build --check --no-header --codex DIR` — compare outputs while removing the exact generated header.

CLI exit codes: `0` for success, `1` for check refusals and other operational errors, and `2` for invalid usage (including unknown flags and incompatible options).

Optional `<codex>/tools.json` configures `lex check` to validate tool commands and flags in fragment code against each tool’s JSON help registry; without it the rule is disabled. An optional `task_command` path (for example, `["run"]`) selects the registry command whose flags apply after a task name.

To print nonempty fragment purposes beneath rules, create `<codex>/purpose.json` containing `{"print": true}` and run `lex build --codex DIR`. The default is off. To roll back, set `print` to `false` or remove the file, then immediately run `lex build --codex DIR`. The derived line is `  Зачем: <цель>`; its indentation keeps it inside a list item. Headings, code blocks and front matter do not print a purpose and are reported by `lex check`. A body containing a line with this marker is rejected when printing is on. `lex check --staged` reads this setting from the index and checks affected outputs when it changes.

Edit a purpose in the fragment header, then run `lex build`; `lex absorb` and `lex import --refresh` reject edited or newly added purpose lines, as well as a missing purpose line for a retained rule, and name the line to put back or delete. A rule removed together with its purpose line is accepted, including in the same pass as an edit of a neighbouring rule that keeps its own purpose line or of a neighbouring heading; next to a rule without a purpose, delete the rule in one pass and make the edit in another. This prevents a derived line from becoming a fragment or silently changing its source. After disabling printing, rebuild before using either command. Deploy this lex version to every machine with a staged-check hook before enabling the setting.

Codex layout: `frag/<topic>/<id>.md` (YAML header + body bytes; optional `draft: true`), `manifest/<name>.yaml` (`out`, `source_sha256`, `built_sha256`, `header`, ordered `parts`, and optional fragment hashes). A part without a `fragment_sha256` entry has no recorded hash; empty hash values are read the same way and omitted on the next manifest write. `header: true` adds a generated marker after YAML front matter. Imports start with `header: false`.

Generated headers show codex paths beneath the current home directory as `~/…`; older absolute headers from that codex remain recognized.

To mark a fragment as a rule, add `тип: правило` after the four standard header fields. `lex check` warns when a rule (marked or with any nonempty rule field) has an empty `основание` or `снять_когда`, or when a user quote remains in its text; the closing line `правил без основания: N, без условия снятия: M; фрагментов с цитатой пользователя в тексте: K` gives the number of warnings of each kind; `--refs-only` does not check rules and prints no such line. An empty `цель` is allowed. Refresh matches fragment headers by body first, then by ID when the number of fragments with that slug is unchanged.

An amendment can name each general rule on a separate `переопределяет: TOPIC/FRAGMENT-ID` line after the four standard fields and optional `тип: правило`, before `draft: true` (alongside any `код` lines). Fill at least one of `цель` and `основание`. Run `lex override-confirm --codex DIR FRAGMENT` to record the current body hash for each rule and update the containing manifests; repeat after reviewing a changed rule. Missing rules and broken links cannot be confirmed. Refresh updates IDs when it can match the old body; if another old rule occupies the ID, it records `переопределяет_обрыв: OLD-ID` until a person replaces that line with the correct `переопределяет:`. `lex override-count --codex DIR` lists rules by decreasing amendment count, with each output and fragment ID. These fields do not appear in built output.

Rule-to-code links follow `тип: правило` and precede `draft: true`. Add one `код: TARGET` line per target. A target is an absolute path to a mechanism card (`.md`), or an absolute repository path, package path and Go test name separated by colons, for example `/work/project:internal/check:TestRule` (use `.` for the repository root). Run `lex code-confirm --codex DIR FRAGMENT`, with the fragment path or its ID relative to `frag`, to record each target's SHA-256 and the body SHA-256 and update all containing manifests. Confirm again after reviewing a change. Card hashes exclude `<!-- stamp: … -->` lines; test hashes cover the function declaration, excluding neighbouring tests. Missing targets cannot be confirmed. Existing snapshots made with the previous hashing scheme need to be confirmed again.

`lex check` warns about changed, missing or unconfirmed links without changing its exit status, with one warning per cause. Full checks examine all fragments, including records; `--staged` examines indexed fragments in touched manifests and changed records (targets are read from disk); `--outputs-under` examines selected manifests; `--refs-only` does not examine code links. `lex code-debt --codex DIR` lists all mismatches and returns 0 even when the list is nonempty. Refresh matches headers by body first, then ID; links of unrecognized fragments are retained without duplicates in `code-link-debt.json` and listed as lost. Confirming a target on any fragment removes all lost entries for that target. To remove them without confirmation, run `lex code-debt --codex DIR --drop TARGET`; it fails if the target has no lost entries. Drop does not suppress mismatches on existing fragments.

To keep a rule as a record without putting it in any generated file, explicitly add `запись: true` before `draft: true`, and keep the fragment out of all manifests. An unmarked orphan remains an error; removing a rule through `absorb` does not create a record. A record cannot be built through a manifest. Existing lex binaries cannot parse the new header fields: deploy the updated lex to every machine that builds the codex before adding any of them.
